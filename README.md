# offerbot — `.buy` для подарков Telegram

Ты печатаешь команду в любом чате — в чате появляется оффер с превью подарка
и двумя кнопками.

```
.buy stars 1500 plushpepe 1234 en 6h
```

```
┌─────────────────────────────┐
│   [ картинка Plush Pepe ]   │   ← превью, прибито к ссылке подарка
└─────────────────────────────┘
BUY · Plush Pepe #1234

Price: 1,500 Stars (≈ $23)
Valid for: 6h · until 14:53 UTC
Escrow / hold: fine
From: @your_username

[ Accept ]  [ Decline ]
```

Кто-то нажимает **Accept** — сообщение само превращается в инструкцию по
передаче:

```
┌─────────────────────────────┐
│   [ картинка Plush Pepe ]   │
└─────────────────────────────┘
OFFER ACCEPTED

Plush Pepe #1234 — 1,500 Stars

@buyer accepted the offer.

Hand the gift over to @your_username.
Open the recipient's profile with the button below and send the
NFT from the gift menu. Confirm the deal in DM once it is done.

Accepted at 14:12 UTC

[ Transfer NFT ]   ← открывает профиль получателя
```

На русском — то же самое словами «ОФФЕР ПРИНЯТ», «Передайте подарок
пользователю @...», кнопка «Передать НФТ». Язык карточки берётся из команды,
а не из настроек бота.

## Важное ограничение платформы

**Inline-кнопки может отправлять только бот.** В Telegram API аккаунт человека
не может ни прикрепить кнопки к сообщению, ни получить нажатие — callback'и
приходят только ботам. Поэтому архитектура такая:

| Кто | Что делает |
|---|---|
| **Твой аккаунт** (юзербот) | ловит `.buy`, который ты напечатал, и удаляет команду |
| **Бот-компаньон** | постит карточку с кнопками, обрабатывает нажатия, закрывает оффер по времени |

Значит бот должен быть **участником чата** с правом писать. Админом быть не
обязательно.

Если бота в чате нет или `BOT_TOKEN` не задан — карточку постит сам аккаунт,
**без кнопок**, редактируя твою команду на месте (так работало раньше: проходит
в чатах, куда ботов не пускают, и в слоумоде). Оффер важнее своих кнопок,
поэтому это не ошибка, а штатная деградация. В этом режиме оффер статичный:
строка «Действует 6ч» останется, но никто не перепишет её по истечении срока.

## Формат команды

```
.buy  <stars|gram>  <цена>  <подарок>  <номер>  <en|ru>  [3h|6h|12h]
.sell <stars|gram>  <цена>  <подарок>  <номер>  <en|ru>  [3h|6h|12h]
```

Парсер намеренно терпимый — команду набирают с телефона посреди сделки.
Все строки ниже дают один и тот же оффер:

```
.buy stars 1500 plushpepe 1234 en 6h
.buy 1500 stars plushpepe 1234 en 6h
.buy stars 1500 PlushPepe-1234 en 6h
.buy stars 1500 plushpepe #1234 en 6h
.buy 6h 1500stars plush pepe 1234 en
```

| Элемент | Варианты |
|---|---|
| Префикс | `.` `!` `/` |
| Сторона | `buy` `sell` `b` `s` `куплю` `продам` `покупаю` `продаю` |
| Валюта | `stars` `star` `⭐` `звёзды` · `gram` `ton` `💎` `тон` |
| Цена | `1500` · `12.5` · `12,5` · `1500stars` |
| Подарок | `plushpepe` · `Plush Pepe` · `plush-pepe` · `PlushPepe-1234` |
| Номер | отдельным числом или `#1234` |
| Язык | `en` `eng` `english` · `ru` `rus` `рус` |
| Срок | `3h` `6h` `12h` `30m` `1d` `3ч` `90мин` — от 5m до 7d |

Валюту, язык и срок можно писать в любом месте команды. Срок разбирается
раньше чисел, поэтому `6h` никогда не будет понято как цена. Если срок не
указан — берётся `DEFAULT_TTL` (по умолчанию 6h).

Единственная настоящая двусмысленность — цена и номер подарка оба числа. Она
решается по порядку из документации: **первое число — цена, последнее —
номер**. `#1234` снимает вопрос совсем.

Не разобралась команда → она превращается в короткую подсказку, которая через
`ERROR_TTL` секунд сама удаляется.

## Кто какую кнопку может нажать

Оффер бывает публичным или адресным. Если команда отправлена **ответом на
сообщение** — оффер адресован этому человеку, и только он может его принять
или отклонить. Без ответа оффер публичный.

| | Публичный оффер | Адресный оффер |
|---|---|---|
| **Accept** | любой, кроме автора; кто первый — того оффер | только адресат |
| **Decline** | автор (= отменить оффер) | автор или адресат |

Принять свой же оффер нельзя. Второму нажавшему бот отвечает, что оффер уже
закрыт — гонка исключена на уровне SQLite, одним условным `UPDATE`, а не
проверкой в памяти.

Кому уходит подарок, зависит от стороны оффера:

- `.buy` — автор платит, значит подарок уходит **автору**, а передаёт тот, кто
  принял;
- `.sell` — автор владеет подарком, значит передаёт **он**, а получает тот,
  кто принял.

Кнопка «Передать НФТ» всегда открывает профиль того, **кто должен получить**
подарок.

## Срок жизни оффера

Открытые офферы лежат в SQLite (`DB_PATH`), поэтому перезапуск процесса их не
теряет. Раз в `SWEEP_INTERVAL` секунд бот проверяет просроченные, переписывает
их карточки в «ОФФЕР ИСТЁК» и снимает кнопки. Нажатие на просроченный оффер
тоже закрывает его на месте — на случай, если свип ещё не дошёл.

## Установка

```bash
git clone <this repo> && cd lzt-bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В `.env` нужно вписать:

1. `TG_API_ID` и `TG_API_HASH` — <https://my.telegram.org/apps>;
2. `BOT_TOKEN` — создать бота у [@BotFather](https://t.me/BotFather);
3. добавить этого бота в чаты, где нужны кнопки.

Посмотреть все состояния карточки, **не подключаясь к Telegram вообще**:

```bash
python -m offerbot check '.buy stars 1500 plushpepe 1234 ru 6h'
```

Запуск:

```bash
python -m offerbot                 # первый вход спросит телефон и код
python -m offerbot login           # выдаст session string для сервера
```

## Как сделано превью

Превью не оставлено на усмотрение Telegram. Ссылка подарка прикрепляется
явно, как `InputMediaWebPage`:

```python
await client(SendMediaRequest(
    peer=peer,
    media=InputMediaWebPage(
        url="https://t.me/nft/PlushPepe-1234",
        force_large_media=True,   # большая картинка
        optional=True,            # нет страницы — пост всё равно уйдёт
    ),
    message=text, entities=entities,
    invert_media=True,            # картинка НАД текстом
    reply_markup=offer_keyboard(offer_id, lang),
))
```

Это даёт три вещи, которых не даёт обычная ссылка в тексте: превью привязано
именно к подарку (а не к первой попавшейся ссылке в сообщении), картинка
крупная, и она стоит над текстом. `optional=True` — страховка: если номера
подарка не существует или Telegram не смог забрать страницу, сообщение
отправится без картинки, а не упадёт.

При каждой правке карточки медиа передаётся заново — иначе превью остаётся на
усмотрение сервера, а картинка здесь и есть смысл поста.

Ссылка подарка: `https://t.me/nft/<Slug>-<номер>`, где slug — название
коллекции в CamelCase без пробелов и апострофов (`Durov's Cap` → `DurovsCap`).
Известные коллекции лежат в `offerbot/gifts.py`; новая добавляется одной
строкой или через `GIFT_ALIASES_FILE`. Незнакомое название всё равно даст
ссылку, но карточка честно припишет «проверь ссылку».

### Кнопка на профиль

«Передать НФТ» строится тремя способами, от самого честного к запасному:

1. `InputInlineButtonTypeUserProfile` — открывает карточку профиля; боту нужен
   access hash пользователя, а он есть только для тех, кого бот видел
   (например, для того, кто сам нажал кнопку);
2. ссылка `https://t.me/<username>` — работает для любого, у кого есть юзернейм;
3. `tg://user?id=` — последний вариант для пользователя без юзернейма.

## Структура

| Файл | Зачем |
|---|---|
| `offerbot/parser.py` | разбор команды → `Offer` (включая срок) |
| `offerbot/gifts.py` | slug'и коллекций, ссылка `t.me/nft/...` |
| `offerbot/render.py` | карточка во всех состояниях, кнопки, тексты на en/ru |
| `offerbot/money.py` | форматирование чисел без системных локалей |
| `offerbot/rates.py` | курс TON с кэшем; падает в «без курса», а не в ошибку |
| `offerbot/store.py` | SQLite: офферы, атомарный accept, истечение |
| `offerbot/buttons.py` | inline-клавиатуры и кнопка на профиль |
| `offerbot/bot.py` | бот: постинг, нажатия, свип просроченных |
| `offerbot/poster.py` | доставка от аккаунта (режим без кнопок) |
| `offerbot/handlers.py` | хендлер исходящих сообщений аккаунта |
| `offerbot/config.py` | конфиг из окружения |

Всё, кроме доставки в сеть, — чистая логика. Поведение кнопок, права на
нажатия, гонка при Accept и истечение проверяются на фейковом клиенте, без
сессии и без Telegram:

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

## Безопасность и лимиты

- **Session string = полный доступ к аккаунту.** Без пароля и без запроса 2FA.
  Не коммить, не пересылать, не показывать на скриншоте. `.gitignore` уже
  закрывает `.env`, `*.session` и `session*`.
- **Работай с отдельного аккаунта**, а не с основного, на котором лежат
  подарки.
- Юзерботы — серая зона в ToS Telegram. Этот бот намеренно умеет только одно:
  оформить то, что ты и так собирался написать. Массовая рассылка и письма в
  ЛС незнакомым людям — главный путь к `PeerFloodError` и ограничению
  аккаунта.
- `FLOOD_SLEEP_THRESHOLD` отдаёт короткие флуд-ожидания Telethon; длинные
  возвращаются тебе уведомлением с числом секунд, вместо того чтобы молча
  висеть.
- Бот подтверждает сделку только на словах. Он **не гарант**: он не держит
  подарок и не переводит деньги, а лишь фиксирует, кто согласился и кому
  передавать. Эскроу — отдельная история.
- `python -m offerbot check` ничего не отправляет — им можно крутить шаблоны
  безопасно.
